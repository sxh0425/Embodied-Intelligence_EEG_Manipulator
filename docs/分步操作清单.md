### 1.1 建独立的 conda 环境

> 不要在 `base` 里装东西。独立环境的好处是：以后上云 GPU 时，你的环境可以 1:1 复现。

```bash
conda create -n eeg-arm python=3.11 -y
conda activate eeg-arm
pip install "mujoco<3.11"
pip install numpy scipy matplotlib gymnasium
```

**为什么用 Python 3.11 而不是 3.13**：你系统上有 3.13.3，但 Intel macOS 上部分科学计算包没有预编译 wheel，会退化成源码编译（慢且容易失败）。3.11 是最稳的版本。

**为什么是 `mujoco<3.11`** ★ 这个坑一定要记住

MuJoCo 官方从 **3.11.0 开始停止发布 macOS x86_64（Intel）的预编译包**，只保留 Apple Silicon 的 arm64：

| 版本 | macOS Intel (x86_64) wheel |
|---|---|
| ≤ 3.10.0 | ✅ 有 |
| ≥ 3.11.0 | ❌ 无（只有 arm64） |

如果直接 `pip install mujoco`，pip 会拿到最新的 3.13.x，发现没有 Intel 的 wheel，就回落到源码包 `mujoco-x.y.z.tar.gz` 去现场编译。编译需要 CMake 等一堆工具，于是你会看到：

```
Failed building wheel for mujoco
error: failed-wheel-build-for-install
```

**这不是你操作错了，是上游砍掉了 Intel Mac 支持。** 记住这条规则：**在这台机器上装任何包，只要报 `Failed building wheel`，第一反应就是查 PyPI 上有没有你这个平台的预编译包，然后降版本。**

（验证过的版本组合：`mujoco 3.10.0` + `numpy 2.4.6` + `scipy 1.17.1` + `matplotlib 3.11.2` + `gymnasium 1.3.0` on Python 3.11.13 / macOS 15.7.8 Intel）

**国内网络提速**：如果 pip 很慢，加清华源

```bash
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple numpy scipy matplotlib mujoco gymnasium
```

**验证**：

```bash
conda activate eeg-arm
python -c "import mujoco, numpy, scipy; print('mujoco', mujoco.__version__); print('numpy', numpy.__version__)"
```

期望输出 `mujoco 3.x.x` 和 `numpy 1.26.x`（或 2.x）。

### 1.2 拿到 MuJoCo Menagerie 模型库

模型库很大（全量 400 MB+），所以用「镜像 + 浅克隆 + 稀疏检出」只拿 Panda 这一个机器人：

```bash
mkdir -p assets && cd assets

cd mujoco_menagerie
```

**为什么要加镜像前缀**：在国内，`github.com` 本身能通，但 git clone 实际拉数据的 `codeload.github.com` 经常超时，表现就是 clone 卡在 88 KB 左右不动。`ghfast.top` 是可用代理（实测 8 秒拉完）。如果这个镜像哪天挂了，同类可替换：`ghproxy.net`、`gitclone.com`。

**为什么用 `--sparse`**：只检出 `franka_emika_panda` 目录，最终 43 MB，而不是全量 400 MB。

拉完后确认这个文件存在：

### 1.3 第一个 MuJoCo 脚本

新建 `robotics/01_load_panda.py`。

> **自己敲一遍，不要复制粘贴。** 你现在的目标是建立"手感和调试能力"，复制粘贴会把报错信息变成黑箱。

```python
import mujoco
import numpy as np

MODEL_PATH = "assets/mujoco_menagerie/franka_emika_panda/scene.xml"

model = mujoco.MjModel.from_xml_path(MODEL_PATH)
data = mujoco.MjData(model)

print("nq (广义坐标数):", model.nq)   # 期望 9
print("nv (自由度)    :", model.nv)   # 期望 9
print("nu (执行器数)  :", model.nu)   # 期望 8

print("\n--- joints ---")
for i in range(model.njnt):
    name = mujoco.mj_id2name(model, mujoco.mjtObj.mjOBJ_JOINT, i)
    print(f"  {i}: {name}  qposadr={model.jnt_qposadr[i]}")

print("\n--- bodies ---")
for i in range(model.nbody):
    print(f"  {i}: {mujoco.mj_id2name(model, mujoco.mjtObj.mjOBJ_BODY, i)}")

# mj_forward: 只做一次前向计算，不推进时间
mujoco.mj_forward(model, data)

print("\nqpos:", np.round(data.qpos, 4))

# 末端位姿：用末端 body "hand" 的坐标系
hid = mujoco.mj_name2id(model, mujoco.mjtObj.mjOBJ_BODY, "hand")
print(f"\nhand body id = {hid}")
print("位置:", np.round(data.xpos[hid], 4))
print("姿态矩阵:\n", np.round(data.xmat[hid].reshape(3, 3), 4))
```

**这个脚本你一定要弄懂的几件事**

| 概念 | 含义 |
|---|---|
| `nq` vs `nv` | `nq` 是广义坐标维度，`nv` 是自由度。这里都是 **9** = 7 个手臂关节 + 2 个手指关节。带浮动基座的机器人（如人形）会出现 `nq > nv` |
| `nu = 8` | **执行器数 ≠ 关节数**。7 个手臂电机 + 1 个夹爪电机（两根手指被约束耦合，一起动） |
| `mj_forward` vs `mj_step` | `mj_forward` 只算一次"当前状态下所有量"（位置、速度、力）；`mj_step` 会推进一个时间步。**做运动学验证时用 `mj_forward`** |
| `body` vs `site` | `body` 是有质量和惯量的刚体，构成运动链；`site` 是挂在 body 上、没有质量的"标记坐标系"，用来描述感兴趣的点（末端执行器、传感器位置）。能拿到 site 就优先用 site |
| `data.xpos` / `data.xmat` | 世界坐标系下每个 body 的位置和姿态矩阵，只有 `mj_forward` 之后才有效 |

> **实测提醒（很多教程在这里写错）**：`franka_emika_panda/scene.xml` 里**一个 site 都没有**（`model.nsite == 0`）。
> 网上常见的 `attachment_site` 在这个模型里不存在，`mj_name2id` 会返回 `-1`，接着 `site_xpos[-1]` 就会取到空数组报 `IndexError`。
> 上面改用末端 body `hand`，效果等价。
> **记住这条通用习惯：只要 `mj_name2id` 返回 -1，第一件事就是先打印出所有名字，看真实叫什么。**

**再加上可视化**（另存为 `robotics/02_view_panda.py`）：

```python
import mujoco
import mujoco.viewer   # 必须显式 import，只 import mujoco 是不够的

model = mujoco.MjModel.from_xml_path("assets/mujoco_menagerie/franka_emika_panda/scene.xml")

# launch 会同时启动物理循环和可视化窗口，阻塞直到你关掉窗口
```

**优化（先建立概念）**
- [ ] 能解释梯度下降、学习率的影响
- [ ] 知道**最小二乘**在解什么，能写出正规方程
- [ ] 知道**二次规划 QP** 的形式（后面带约束的 IK 会用到）

**动手练习（这是真正的验收环节）**

```python
import numpy as np

rng = np.random.default_rng(0)
A = rng.normal(size=(100, 5))     # 过定方程组：100 个方程，5 个未知数
b = rng.normal(size=100)

# 方法 1：正规方程
x1 = np.linalg.solve(A.T @ A, A.T @ b)

# 方法 2：numpy 内置
x2, *_ = np.linalg.lstsq(A, b, rcond=None)

# 方法 3：用 SVD 手写伪逆（这个最重要，理解完你就懂 IK 的数值解法了）
U, S, Vt = np.linalg.svd(A, full_matrices=False)
x3 = Vt.T @ np.diag(1.0 / S) @ U.T @ b

print(np.allclose(x1, x2), np.allclose(x2, x3))
```

三种方法结果应该一致。**这三行伪逆的代码，就是你一个月后写 IK 的核心。**

**numpy 向量化练习（直接为后面铺路）**

```python
import numpy as np
import time

P = np.random.rand(500, 3)   # 500 个点
Q = np.random.rand(500, 3)   # 另外 500 个点

# 任务：算出 500×500 的距离矩阵，不允许出现 for 循环
# 提示：利用广播 (P[:, None, :] - Q[None, :, :])，再对最后一维求范数
D = np.linalg.norm(P[:, None, :] - Q[None, :, :], axis=-1)
assert D.shape == (500, 500)
```

这个 `(N, 1, d) - (1, M, d)` 的广播技巧，是后面算 Jacobian、批量做碰撞检测的基本手法。**必须练到条件反射。**
