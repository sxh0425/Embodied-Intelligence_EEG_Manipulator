## 0. 先分清两种「不会」★ 这一条能省你几个月

卡住的时候，先分类：

| | A 类：不懂概念 | B 类：不知道 API |
|---|---|---|
| 表现 | "我完全不明白雅可比是什么" | "我不知道该用哪个字段" |
| 例子 | 为什么力臂 = 位移 / 转角 | `xmat` 是干嘛的？`jnt_pos` 在哪？ |
| 怎么解决 | 回去读教案 / 查书 / 问人 | **自己 30 秒就能查出来** |
| 危险程度 | 正常，需要时间 | ⚠️ **最容易被误判成 A 类** |

**绝大多数"我太笨了"的时刻，其实是 B 类。** 你看着 EX5 那道题发懵，不是因为你不懂点到直线的距离，而是因为：

- 你不知道 `model.jnt_bodyid[j]` 能告诉你关节挂在哪个 body 上
- 你不知道 `data.xmat` 要先 `.reshape(3, 3)` 才能做矩阵乘法
- 你不知道关节轴在 body 的**局部坐标系**里，要先转到世界坐标系

**这三个都是 B 类问题。** 它们不是"知识"，是"接口"。而接口是可以当场查出来的——甚至不需要查文档，写三行代码就能问出来。

## 1. 探索式编程：四个动作

这是你从今天起要一直用的方法。**核心思想：与其猜，不如直接问程序。**

### 动作 ① `dir()` —— 有什么

不知道一个对象有哪些字段时：

```python
>>> [n for n in dir(model) if 'jnt' in n]
['body_jntadr', 'body_jntnum', 'dof_jntid', 'jnt', 'jnt_actfrclimited',
 'jnt_actfrcrange', 'jnt_actgravcomp', 'jnt_actuatorid', 'jnt_axis',
 'jnt_bodyid', 'jnt_dofadr', 'jnt_group', 'jnt_limited', 'jnt_margin',
 'jnt_pos', 'jnt_qposadr', 'jnt_range', 'jnt_solimp', ...]
```

**一秒钟就找到了 `jnt_axis`、`jnt_pos`、`jnt_bodyid`。** 这正是你卡住的那几个字段。

> `dir()` 列出对象的所有属性。加个 `if '关键词' in n` 过滤，比翻文档快得多。

### 动作 ② `type()` / `.shape` —— 长什么样

找到了字段，但不知道它是什么形式：

```python
>>> m.jnt_axis.shape
(9, 3)
>>> m.jnt_axis.ndim
2
```

**立刻能推断出：9 行 = 9 个关节，3 列 = 轴的 xyz 分量。** 所以 `jnt_axis[0]` 就是 joint1 的轴。

同样：

```python
>>> d.xmat.shape
(12, 9)
>>> d.xpos.shape
(12, 3)
```

12 个 body；位置是 3 个数，朝向是 9 个数 —— **9 就是 3×3 矩阵被展开的结果**，所以做矩阵乘法前必须 `.reshape(3, 3)`。

**这个 `.shape` 的检查，能省掉你 90% 的"为什么报维度错误"。**

### 动作 ③ 打印内容 —— 具体是什么

```python
>>> print(m.jnt_axis)
[[0. 0. 1.]     ← joint1
 [0. 0. 1.]     ← joint2
 [0. 0. 1.]     ← joint3
 [0. 0. 1.]     ← joint4
 [0. 0. 1.]     ← joint5
 [0. 0. 1.]     ← joint6
 [0. 0. 1.]     ← joint7
 [0. 1. 0.]     ← finger_joint1
 [0. 1. 0.]]    ← finger_joint2
```

**一眼看出**：7 个手臂关节的轴都是 `[0,0,1]`，手指的是 `[0,1,0]`，而且第 8、9 行确实就是两根手指。

> ⚠️ **但注意**：这里的 `[0,0,1]` 是**局部坐标系**里的轴。第 3 课实验 2 里 joint1 的轴"恰好"是世界 z 轴，是因为 link1 的朝向刚好是单位矩阵。**换个关节就不成立了** —— 这正是 warmup 第 8 级的考点。

### 动作 ④ 验证猜测 —— 是不是我猜的

打印出来了，但不确定自己的理解对不对？**构造一个你知道答案的测试。**

这是最重要的一步，也是最容易被跳过的：

```python
# 我猜：第 0 行是 joint1，第 7 行是 finger_joint1
# 验证：数一下行数对不对
>>> m.jnt_axis.shape[0]
9
>>> m.njnt
9
# 对上了 ✓
```

**"猜 → 构造测试 → 验证"这个循环，就是工程能力的全部。** 你不需要一开始就知道答案，你需要的是有能力当场验证自己的想法。

## 2. 完整示范：如果我不知道 `xmat` 是什么

假设第 3 课你读到这里卡住了：

> 「`data.xmat[hid]` 是什么？为什么还要 `.reshape(3, 3)`？」

**不要问人。按顺序做这四步：**

```python
import mujoco, numpy as np
m = mujoco.MjModel.from_xml_path(...)
d = mujoco.MjData(m); mujoco.mj_forward(m, d)

# ① 找：有哪些跟位置/朝向有关的字段？
print([n for n in dir(d) if n.startswith('x')])
# → ['xanchor', 'xfrc_applied', 'xipos', ..., 'xmat', 'xpos', ...]

# ② 看形状
print(d.xpos.shape, d.xmat.shape)
# → (12, 3) 和 (12, 9)

# ③ 看内容
hid = mujoco.mj_name2id(m, mujoco.mjtObj.mjOBJ_BODY, "hand")
print(d.xmat[hid])
# → [ 0.7071  0.7071  0.  ...]  9 个数

# ④ 验证：9 个数能不能变成一个 3×3 矩阵？它是不是旋转矩阵？
R = d.xmat[hid].reshape(3, 3)
print(R @ R.T)          # 应该约等于单位矩阵（旋转矩阵的性质）
print(np.linalg.det(R)) # 应该等于 1
```

跑完这四步，你会**自己**得出结论：`xmat` 是每个 body 的 3×3 朝向矩阵，被展开成 9 个数存储；`.reshape(3,3)` 是为了恢复成矩阵便于乘法。而且你还额外验证了它确实是旋转矩阵（正交且行列式为 1）—— 这是第 1 章要手推的内容，你现在已经用代码看见了。

**这比看任何教程都牢。** 因为是你自己验证出来的。

## 3. 大题拆成微步骤：EX5 是怎么被拆开的

`exercises.py` 里的 EX5（求力臂）单独看确实陡。它其实由 4 个独立的小步骤组成：

```
EX5「求末端到关节转轴的垂直距离」
 │
 ├─ 小步骤 A：转轴经过哪个点？           →  warmup 第 9 级
 ├─ 小步骤 B：转轴朝哪个方向？           →  warmup 第 8 级
 ├─ 小步骤 C：末端在哪？                 →  warmup 第 4 级
 └─ 小步骤 D：点到直线的距离怎么算？     →  warmup 第 10 级
```

**每一步单独看都不难。** 难的是不知道要先拆开。

所以 `robotics/warmup.py` 就是把这四个小步骤单独拿出来，每级一个，每级都给你确切的字段名（消除 B 类问题），只让你思考逻辑。

**从今天起，遇到不会的大题，先做这一件事：**

> 在白纸上把它拆成"我确定会做的"和"我确实不会的"两部分。
> 然后**只针对"确实不会的"那一小块**去查、去问、去试。

不要对着整道题发懵——那没有出路。

## 4. 怎么问问题才有效（包括问我）

**❌ 无效的问法：**
> "EX5 怎么做？"
> "为什么我的代码不对？"

这种问法我只能给你完整答案，而完整答案对你的理解帮助很小。

**✅ 有效的问法——三段式：**

```
1. 我预期会发生什么
2. 实际发生了什么（贴报错 / 贴输出）
3. 我已经试过什么

例子：
  「EX5 里我预期把 jnt_axis 直接用就行，
   但报错说 shape (3,) 和 (3,3) 不能相乘。
   我已经试过用 xmat 乘 jnt_axis，但不确定
   要不要 reshape，也不知道该用哪个 body 的 xmat。」
```

**为什么这个格式有效**：它逼你先精确描述问题。**一半的情况下，你在写这三段的过程中就自己找到答案了**——这叫橡皮鸭调试法，是真实存在的现象，不是玩笑。

而如果没找到，我也能精确地补上你缺的那一块，而不是把整个答案倒给你。

## 5. 30 分钟法则

```
卡住
 │
 ├─ 是 B 类（不知道 API）？ → 用第 1 节的四个动作，自己查。通常 5 分钟内解决
 │
 └─ 是 A 类（不懂概念）？
      │
      ├─ 先试着拆成小步骤，看能不能绕过
      │
      └─ 卡超过 30 分钟 → 停。去看教案对应章节，或者来问我
```

**为什么是 30 分钟**：短于 30 分钟就放弃，你失去的是"自己搞明白"的能力增长；长于 30 分钟死磕，你失去的是学习进度和信心。前者更贵，后者更常见。

**还有一条：卡住时不要硬扛着不跳过。** 有些概念（比如雅可比）就是需要在后面反复遇到才会真正懂。先标记一下，往前走，回头再看。

## 6. 关于"太难"这件事

最后说一句实话：

> **`exercises.py` 从 EX4 开始太陡，是我的问题，不是你的问题。**

一道题要同时用 5 个你从没见过的 API、还要组合点到直线的距离公式——这不是"难"，这是**没有搭台阶**。任何人在没有台阶的情况下都会卡住，然后错误地归因成"我不适合学这个"。

**正确的做法是补台阶**，也就是 `warmup.py`：

| 如果你现在… | 那就去… |
|---|---|
| EX4/EX5 完全没头绪 | 做 `warmup.py` 的第 8、9、10 级 |
| EX6 觉得莫名其妙 | 做 `warmup.py` 第 11 级（它就是 EX5 的答案） |
| EX7 不会 | 做 `warmup.py` 第 12 级 |
| EX1~EX3 也不会 | 说明第 1 课还没读透，回去重读第 4、6、7 节 |

**卡住不代表你不适合，只代表台阶不够密。** 工程的常态就是"把一个大问题拆成一堆小问题"——你现在遇到的，恰恰是这个专业最核心的能力训练。

## 8. 小结

```
卡住
 ├─ B 类（不知道 API）
 │    → dir() 找字段     ：有什么
 │    → .shape 看形式     ：长什么样
 │    → print 看内容      ：具体是什么
 │    → 构造测试验证      ：是不是我猜的          ← 最关键
 │
 └─ A 类（不懂概念）
      → 拆成微步骤，只攻"确实不会的"那一小块
      → 30 分钟还不行 → 看教案 / 问人

问问题的正确姿势：预期 + 实际 + 试过什么
```
