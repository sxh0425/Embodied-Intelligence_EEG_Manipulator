# 第 1 课：MuJoCo 到底是什么

> 对应代码：`robotics/01_load_panda.py`
> 前置知识：会写 Python、知道矩阵能表示旋转
> 本课结束你能回答：MuJoCo 内部在干什么？`model` / `data` / `qpos` 各是什么？`mj_forward` 到底做了什么？

---

## 0. 一句话回答

**MuJoCo 是一个「物理引擎」（physics engine）**，更准确地说是一个**刚体动力学仿真器**（rigid-body dynamics simulator）。

它的工作流程是：

> 你给它一份「机器人 + 环境」的描述文件 → 它在电脑里模拟这些东西**受力之后怎么动、怎么碰撞**。

名字本身就是缩写：

**Mu**lti-**Jo**int dynamics with **Co**ntact
（带接触的多关节动力学）

- **Multi-Joint**：支持由多个关节连成的机构，比如七自由度的机械臂
- **Contact**：能处理物体之间的碰撞和摩擦——这是物理仿真里最难的部分，也是 MuJoCo 的看家本领

**一段历史，决定了它为什么是今天的主流**：MuJoCo 由 Emo Todorov 在 2001 年开发，此后近二十年一直是**收费的闭源商业软件**。2021 年 DeepMind 把它收购后**开源免费**。从那一刻起，学术界和工业界大规模转向它，现在几乎所有具身智能/强化学习论文的仿真环境都跑在 MuJoCo 上。

---

## 1. 为什么需要它：从「你怎么让机器人在电脑里动起来」说起

假设你要让机械臂学会抓杯子。有两条路：

| | 用真机 | 用仿真 |
|---|---|---|
| 成本 | Franka Panda 约 20–30 万人民币 | 0 |
| 撞坏了 | 维修几万块起，可能几周 | 重启一下 |
| 速度 | 实时（1 秒就是 1 秒） | 可以比实时快几十倍 |
| 重复性 | 每次都有微小差异 | 完全相同，可复现 |
| 危险性 | 会打到人 | 无 |

最后两行才是关键。

**强化学习需要在环境里试几十万到几百万次。** 真机上跑 100 万次，按每次 3 秒算需要 34 天不间断，而且机械臂早就磨损了。仿真里可能只要几小时。

> 所以：**仿真不是为了「好看」，是为了让算法能做得起实验。**

## 2. 物理引擎的本质：一个不断重复的 4 步循环 ★ 本课最重要的一节

这是真正的「底层」。所有物理引擎——MuJoCo、Bullet、PhysX、Drake、Genesis——骨架都是同一个，来自牛顿第二定律：

$$F = ma \quad\Longrightarrow\quad a = \frac{F}{m}$$

已知当前状态，算出所有力，就能算出加速度；对加速度积分，就得到新的速度和新位置：

```python
# 物理引擎的核心，伪代码
位置 = 初始位置
速度 = 初始速度

while True:
    # ① 算力：重力 + 电机力 + 接触力 + 摩擦 + 弹簧阻尼 + ...
    力 = 计算所有力(位置, 速度)

    # ② 算加速度：F = ma  =>  a = F/m
    加速度 = 力 / 质量

    # ③ 积分速度：v_new = v_old + a·dt
    速度 = 速度 + 加速度 * dt

    # ④ 积分位置：p_new = p_old + v·dt
    位置 = 位置 + 速度 * dt
```

**就这四步，循环下去。** MuJoCo、PhysX、游戏引擎，全都长这样。

各家引擎的区别只在这三件事上：

| 差异点 | 说明 | MuJoCo 的做法 |
|---|---|---|
| **接触力怎么算** | 最难的。两个物体撞上时，力应该多大？ | 建模成**凸优化问题**求解，数学上很优雅，且接触非常稳定 |
| **约束怎么处理** | 关节把连杆连起来，数学上是一堆等式约束 | 用**软约束**，允许微小违反，天然稳定且能求导 |
| **积分器阶数** | 精度 vs 速度的权衡 | 默认 Euler（实现上是**半隐式**：先更新速度、再更新位置），可换成 RK4 / implicit |

> **为什么要强调"能求导"**：因为强化学习要靠梯度优化（比如 SAC），如果你的仿真器不可微或者抖动剧烈，算法就训不动。MuJoCo 的数学设计从一开始就考虑了这个。

## 3. 时间步 `dt`：计算机无法处理"连续"

真实世界的时间是连续的，但计算机只能一格一格算。所以要把它切成小片：

```python
dt = 0.002   # 2 毫秒，也就是 500 Hz
```

`dt` 就是上面那个循环里每转一圈代表的时间。

几个直接后果：

- **`dt` 越小，仿真越准，但越慢**（要多算几圈）
- **`dt` 太大，仿真会"炸"**——数值误差累积到发散，你会看到机械臂突然抖动或飞出屏幕
- **"实时仿真"**的意思是：仿真 1 秒 = 真实时间 1 秒。但你可以让它跑得**比实时快**——这正是 RL 训练的基础。你的 Panda 场景 `dt` 就是 0.002

> **这叫"离散化"（discretization）。** 记住这个概念，你以后调仿真时遇到的怪现象，一大半都跟它有关。

## 4. 状态被压缩成一个数组：广义坐标 ★ 第二重要

现在的问题是：**「位置」和「速度」到底要用几个数字表示？**

| 对象 | 需要几个数 | 组成 |
|---|---|---|
| 空间中的一个点 | 3 | (x, y, z) |
| 空间中的一个刚体 | 7 | 位置(3) + 朝向(4，四元数) |
| **Panda 机械臂** | **9** | 7 个手臂关节角 + 2 个手指关节角 |

为什么机械臂只要 9 个？因为它**底座焊死在地上**，不存在"它在哪、朝哪"的问题，只有关节会动。每个转动关节贡献 1 个角度，每个滑动关节贡献 1 个位移。

**把这 9 个数按顺序排成一个数组，就是 `qpos`：**

```
qpos = [ j1  , j2  , j3  , j4  , j5  , j6  , j7  , finger1 , finger2 ]
         └────────── 手臂 7 个关节 ──────────┘   └── 夹爪 2 个 ──┘
```

**为什么一定要挤成一个数组？** 因为引擎内部全是矩阵运算（求逆、分解、求解方程）。统一成向量的形式，才能写成 `M(q)·q̈ + C(q,q̇) = τ` 这样的矩阵方程来高效求解。这是数值仿真的通用做法。

这个数组在数学上叫**广义坐标**（generalized coordinates）——"广义"的意思就是"不限于普通的 xyz 位置，任何能描述系统构型的参数都算"。

**两个容易踩的坑：**

1. **`jnt_qposadr` 是必须的**：`qpos` 第几个数是哪个关节的，不是想当然的。这个模型里刚好一一对应，但带浮动基座的机器人（人形、四足），基座会占掉 `qpos` 的前 7 位，后面全部错位。
2. **关节数 ≠ 执行器数**：`njnt = 9` 但 `nu = 8`。因为两根手指被约束耦合，**一个电机带动两根手指**。所以不要假设"每个关节一个电机"。

## 5. 两个盒子：`model` 和 `data` 为什么要分开 ★ 第三重要

这是 MuJoCo 设计上最重要的一个决定：

| | `model`（`MjModel`） | `data`（`MjData`） |
|---|---|---|
| 是什么 | **机器人的定义 / 图纸** | **这一次仿真的全部状态** |
| 里面装什么 | 连杆尺寸、质量、关节类型、执行器参数、`dt` | `qpos`、`qvel`、`ctrl`，以及算出来的位姿、力、接触 |
| 什么时候生成 | `from_xml_path()` 时**一次编译完成** | `MjData(model)` 时按图纸分配内存 |
| 会变吗 | **永不改变，只读** | **每一步都变，可读可写** |
| 类比 | 汽车的设计图纸 | 这辆车此刻的时速和油量 |

**这解释了你早就该问的问题：为什么几乎所有 MuJoCo 函数都是 `f(model, data)` 两个参数？**

因为任何物理计算都需要两样东西：**「机器人的构造」+「它此刻的状态」**。图纸和状态被彻底分离，函数签名就必然长这样。

**分开的真正好处**——这一点极其重要：

> **同一个 `model`，可以开出成千上万个 `data` 并行跑。**

这正是强化学习训练的做法：一张显卡上同时跑几千个仿真环境，每个环境有自己的 `data`，但共享同一份 `model`。如果两者不分开，这个优化就不可能实现。

---

## 6. `data` 里到底装了什么

记住这个二分法，你以后就不会迷路：

| 类别 | 字段 | 谁负责写 |
|---|---|---|
| **输入 / 状态** | `qpos`（位置）、`qvel`（速度）、`ctrl`（给电机的控制信号） | **你写**（或者由 `mj_step` 更新） |
| **输出 / 派生量** | `qacc`（加速度）、`xpos`/`xmat`（每个 body 的世界位姿）、`qfrc_*`（各种力）、接触信息 | **引擎算** |

关键理解：**`xpos` 和 `xmat` 不是你设置的，是算出来的。**

它们只在 `mj_forward` 或 `mj_step` 被调用**之后**才有效。在调用之前，`data.xpos` 里是没意义的初始值（通常全是 0）。这就是为什么你的 `01_load_panda.py` 里必须**先** `mj_forward` 再读 `xpos`。

## 7. `mj_forward` vs `mj_step`：用时间轴理解

```
时刻 t ： qpos、qvel 已知
   │
   ├── mj_forward(model, data)
   │      输入 qpos/qvel  →  算出全部派生量（xpos, xmat, 各种力）
   │      ✗ 不修改 qpos     ✗ 不推进时间
   │      本质：把状态「翻译」成各种可读量
   │
   └── mj_step(model, data)
          做了两件事：① mj_forward   ② 积分一步
          ✓ 修改 qpos/qvel    ✓ 把时间推到 t + dt
          本质：让时间往前走一格
   │
时刻 t+dt
```

一句话总结：

- **`mj_forward` = 翻译**（只算，不改，不推进）
- **`mj_step` = 翻译 + 走一格**

**为什么这个区分对你特别重要？** 因为你在做运动学（Stage 1 要手写 FK/IK）时，**永远用 `mj_forward`**。它是无副作用的纯计算，你反复调用它 100 次也不会把状态搞乱。如果误用 `mj_step`，时间会一直往前走，重力会让机械臂慢慢下沉，你的数值就对不上了。

## 8. 回到你的代码：`01_load_panda.py` 逐行翻译

```python
model = mujoco.MjModel.from_xml_path(MODEL_PATH)   # 读图纸：解析 XML，编译成内部结构。只做一次
data  = mujoco.MjData(model)                        # 按图纸分配一块状态内存
```

| 代码 | 它在做什么 | 对应的概念 |
|---|---|---|
| `model.nq` | 广义坐标维数 = 9 | 第 4 节 |
| `model.nv` | 自由度维数 = 9（此模型无约束冗余，所以等于 nq） | 第 4 节 |
| `model.nu` | 执行器数 = 8 | 第 4 节的坑 2 |
| `model.jnt_qposadr[i]` | 第 i 个关节的角度存在 `qpos` 的第几位 | 第 4 节的坑 1 |
| `mj_forward(model, data)` | 给定 `qpos`，算出所有 body 的世界位姿 | 第 7 节 |
| `data.xpos[hid]` | `hand` 这个 body 在世界坐标系中的位置 | 第 6 节：派生量 |
| `data.xmat[hid]` | 它的朝向，3×3 旋转矩阵（按行展开成 9 个数） | 第 6 节 |

## 10. 本课小结

```
真实世界                     MuJoCo 内部
─────────                   ─────────────
机器人的零件图纸   ──────→   model （只读，编译一次）
机器人的当前姿态   ──────→   data  （可写，每步都变）
                              └── qpos: 所有关节角挤成一个数组

牛顿第二定律 F=ma  ──────→   四步循环：算力 → 算加速度 → 积分速度 → 积分位置
                              └── 每转一圈 = dt 秒

"现在所有东西在哪" ──────→   mj_forward 算出来（不改状态）
"往前走一小步"     ──────→   mj_step（改状态）
```
