# 教案（Lessons）

> 每写完一个练习脚本，就配一份教案，讲清楚它**底层的原理**。
> 教案只讲"为什么"，代码只负责"怎么做"——两者分开，是为了让你不被代码细节淹没。

## 怎么用

```
① 读教案              ← 建立概念，不求记住，只求有印象
② 做热身关卡           ← warmup.py，每级只加一个新概念，不能跳
③ 填预测再跑实验        ← 大脑被迫建模，猜错即理解
④ 做练习题            ← exercises.py，用代码验证你真的懂了
⑤ 回头重读教案         ← 这时你会发现"原来那句话说这个意思"
```

**② 不能跳。** `exercises.py` 从 EX4 起要同时组合 5 个新 API，直接做必然卡住。
`warmup.py` 就是把这些台阶拆开的版本 —— 卡住了就退回去做热身，这不是降级，是正确做法。

**① 和 ⑤ 都很重要。** 学完再读一遍，收获比第一次读大一倍。

## 关键原则

> **先从"运行代码看结果"改成"先猜结果再运行"。**
>
> 跟着敲代码时，输入是别人给的，大脑全程旁观。
> 先预测再验证时，大脑被迫构建模型。
> **猜错的那一刻，才是理解真正发生的地方。**

## 教案模板（后续课程沿用）

每份教案固定包含：

```
0. 一句话回答这节课的问题
1. 为什么需要这个东西（从问题出发，而不是从定义出发）
2. 底层原理（★ 最重要，要能自己复现推理）
3. 关键公式 / 数据结构
4. 回到你的代码逐行翻译
5. 常见误解与坑
6. 练习题（概念题 + 动手题）
7. 小结 + 通向哪里（和后面的 Stage 挂钩）
```
