## 0. 你卡住的原因是方法问题，不是能力问题

「跟着敲一遍」这种学法有个结构性缺陷：**代码的输入是别人给的，你的大脑没有被要求构建任何模型。**

大脑只有在被迫做预测的时候才会真正建模。所以解法不是"再看一遍教程"，而是换一个循环：

```
❌ 读代码 → 敲一遍 → 运行 → 看输出         （大脑全程旁观）
✅ 读代码 → 猜输出 → 运行 → 对比            （大脑被迫建模，猜错即理解）
```

**猜错的那一刻就是理解发生的地方。** 猜对了说明你已经懂了，猜错了说明你找到了一个具体的、可修复的缺口——这远比"感觉好像懂了"有价值。

`03_experiments.py` 就是按这个循环设计的，5 道题，先填 `PREDICTIONS` 再运行。

## 1. 核心心智模型：两个盒子

MuJoCo 把仿真拆成两个完全分离的东西：

| | `model`（MjModel） | `data`（MjData） |
|---|---|---|
| 是什么 | **说明书 / 图纸** | **此刻的状态** |
| 装什么 | 几根连杆、多长多重、关节是转的还是滑的、电机装在哪 | 当前每个关节的角度、速度、受力 |
| 何时变 | 加载 XML 时生成一次，**之后永不改变** | **每一步都在变** |
| 类比 | 汽车的设计图纸 | 这辆车此刻的时速和油量 |

这解释了一个你早就该问的问题：**为什么几乎所有 MuJoCo 函数都是 `f(model, data)` 两个参数？**

因为任何物理计算都需要两样东西：「机器人的构造」+「它现在的状态」。图纸和状态被彻底分开，是 MuJoCo 设计上最重要的一个决定。

```python
model = mujoco.MjModel.from_xml_path(...)   # 读一次 XML，生成图纸
data  = mujoco.MjData(model)                # 按图纸开一块"状态内存"
```

## 2. `qpos`：所有关节角挤在一个数组里

`data.qpos` 是一个**一维数组**，按顺序装着所有关节的角度。这就是 `nq = 9` 的含义：

```
qpos = [j1, j2, j3, j4, j5, j6, j7, finger1, finger2]
         ↑ 7 个手臂关节              ↑ 2 个手指关节
```

`model.jnt_qposadr[k]` 告诉你「第 k 个关节的角度存在 qpos 的第几位」。这个模型里刚好一一对应，但**不能假设总是这样**——带浮动基座的机器人（人形、四足），基座会占掉 qpos 的前 7 位（3 位位置 + 4 位四元数），后面关节的下标就整体错位了。

**为什么要挤成一维数组？** 因为仿真内核本质上是矩阵运算和方程求解，统一成向量才能高效计算。这是数值仿真的通用做法，不是 MuJoCo 特有的。

**顺带一个反直觉点**：`nu`（执行器数）≠ `njnt`（关节数）。这里是 8 个执行器、9 个关节——因为两根手指被约束耦合，只用一个电机驱动。

## 3. `mj_forward`：它不是「跑仿真」，它是「翻译」

这是我最想让你建立的一个认知。

**`mj_forward` 不推进时间，一行都不推进。** 它做的事情是：

```
输入：qpos（一堆关节角）
  ↓  按运动链一层层算下去
输出：xpos / xmat（每个 body 在世界坐标系里的位置和姿态）
```

**这就是正运动学（FK）本身。** 你在 `01_load_panda.py` 里那句 `mujoco.mj_forward(model, data)`，已经用上 FK 了，只是当时不知道那个名字。

对比一下真正「跑仿真」的那个：

| 函数 | 做什么 | 会改 qpos 吗 | 会推进时间吗 |
|---|---|---|---|
| `mj_forward(model, data)` | 给定 qpos，算出所有位姿和力 | ❌ 不会 | ❌ 不会 |
| `mj_step(model, data)` | `mj_forward` + 积分一个时间步 | ✅ 会 | ✅ 会 |

`mj_forward` 是无副作用的纯计算。所以**做运动学验证时永远用它**——你不会不小心把状态搞乱。

实验 5 会让你亲手验证这一点：连续调 100 次 `mj_forward`，`qpos` 纹丝不动；换成 100 次 `mj_step`，关节角就漂了。

## 4. body 树：机械臂是一棵「挂满积木的树」

这个模型的骨架：

```
world
 └─ link0（底座，焊死在地上）
     └─ link1 ──[joint1]── 绕 z 转
         └─ link2 ──[joint2]── 绕 y 转
             └─ link3 ──[joint3]
                 └─ link4 ──[joint4]
                     └─ link5 ──[joint5]
                         └─ link6 ──[joint6]
                             └─ link7 ──[joint7]
                                 └─ hand
                                     ├─ left_finger
                                     └─ right_finger
```

两条规则，理解了就够用：

1. **每个 body 都挂在父节点上**，相对父节点的安装偏移和朝向写死在 XML 里（`body_pos` / `body_quat`）。
2. **关节转动时，它下游的整棵子树跟着一起转。** 上游毫不知情。

但实验 3 会给你一个反直觉的结果：转 `joint1` 时，`link1/link2/link3/link5/link6` 的**位置并没有变**。

为什么？因为**它们恰好都在 joint1 的转轴上**（到 z 轴距离 = 0）。转轴上的点旋转后还是原地不动，只有偏离转轴的点才会扫出圆弧。

所以更准确的表述是：

> **关节转动时它下游整棵子树都在转，但只有「不在转轴上的点」才会产生位移。**

这个区分在撞到「奇异位形」时会变得非常重要。

## 5. `位移 ≈ 力臂 × 转角` —— 雅可比的种子

实验 4 是整个脚本里最值钱的一道。单独把每个关节转 0.3 rad，看末端移动多远：

| 关节 | 末端到该转轴的距离 r | 预测 r×0.3 | 实测位移 |
|---|---|---|---|
| joint1 | 0.0880 | 0.02640 | 0.02630 |
| joint2 | 0.5995 | 0.17985 | 0.17917 |
| joint3 | 0.0880 | 0.02640 | 0.02630 |
| joint4 | 0.2771 | 0.08312 | 0.08281 |
| joint5 | 0.0880 | 0.02640 | 0.02630 |
| joint6 | 0.1385 | 0.04156 | 0.04141 |
| **joint7** | **0.0000** | **0.00000** | **0.00000** |

（预测和实测有微小差异是正常的——公式 `r×θ` 只在角度很小时严格成立，精确值要用 `2r·sin(θ/2)`。）

三个结论，一个比一个重要：

1. **规律极简单**：末端移动距离 ≈ 到转轴的垂直距离 × 转角。这个"距离"就是**力臂**。
2. **不同关节的杠杆效应差几十倍**：joint2 转 0.3 弧度末端跑 18 厘米，joint7 转同样角度末端纹丝不动。这张表背后的数学就是**雅可比矩阵**——它每一列就是一个关节的"杠杆比"。
3. **joint7 的位移是 0**：末端正好落在 joint7 的转轴上（r = 0）。转它只是让夹爪原地自转。这就是「奇异位形」的雏形——在那个方向上，你**没法**通过转关节让末端动起来。

记住这个直觉，Step 3 推雅可比的时候你会觉得"这不就是我早就知道的事吗"。

## 6. 一张表总结你写过的代码

| 代码 | 它在做什么 | 背后的名字 |
|---|---|---|
| `MjModel.from_xml_path(...)` | 读图纸，生成只读的模型 | 模型加载 / MJCF 解析 |
| `MjData(model)` | 按图纸分配一块状态内存 | 状态初始化 |
| `model.nq / nv / nu` | 广义坐标数 / 自由度数 / 执行器数 | 系统维度 |
| `model.jnt_qposadr[i]` | 第 i 个关节的角度存在 qpos 的第几位 | 索引映射 |
| `data.qpos` | 所有关节角挤成的向量 | 广义坐标 |
| `mj_forward(model, data)` | qpos → 所有 body 的世界位姿 | **正运动学 FK** |
| `data.xpos[i] / xmat[i]` | 第 i 个 body 的位置 / 3×3 姿态矩阵 | 世界坐标系下的位姿 |
| `mj_step(model, data)` | 前向计算 + 积分一个时间步 | 仿真推进 |
| `viewer.launch(model, data)` | 起物理循环 + 开窗口 | 可视化 |

你现在回头再看 `01_load_panda.py`，应该每一行都能说清它在干嘛了。**如果不能，指出来，那才是你该补的地方。**

## 7. Step 2 预告：FK 的真身长什么样

既然你已经知道 `mj_forward` 就是在算 FK，那不妨看看 FK 到底长什么样。核心只有三行：

```python
R = np.eye(3); p = np.zeros(3)          # 从世界坐标系出发
for 每一节 body，从底座到末端:
    p = p + R @ model.body_pos[b]        # ① 平移：这一节相对父节点的安装偏移
    R = R @ quat2mat(model.body_quat[b]) # ② 乘上这一节相对父节点的安装朝向
    if 这一节带关节:
        R = R @ axis_angle(axis, qpos[j])# ③ 再乘上关节转过的角度
# 循环结束时，p 和 R 就是末端的位姿
```

**FK 的本质就这么简单：把每一段的「旋转+平移」依次乘起来。**

（顺带一提，②和③的顺序是**不能交换**的。我实际验证过：顺序写反的话，末端位置会差 0.19 米。这就是为什么第 1 章要先啃明白 SE(3) 和变换的顺序。）

具体怎么做放到了 Step 2，那时你要自己从零写一遍，并用 `mj_forward` 验证误差 < 1e-6。**现在不用动手，只要看懂这个结构就够了。**
