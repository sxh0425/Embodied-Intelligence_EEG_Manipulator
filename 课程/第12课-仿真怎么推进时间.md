# 第 12 课 · 仿真怎么推进时间

**目标**：让 warmup 第 12 级显示 ✅（最后一关）

## 1. 原理：仿真里根本没有"时间"

电脑里没有一个连续流动的时间。**仿真的真相是：一小步一小步地算。**

```
第 0 步：物体在 (0, 0, 10)，速度 0
第 1 步：算出新速度 -> 算出新位置
第 2 步：算出新速度 -> 算出新位置
... 重复一万次
```

每次间隔的这个小时间叫 **dt**（时间步长）。在 MuJoCo 里是 `model.opt.timestep`，Franka 这个模型是 0.002 秒。

**"仿真"听着玄，其实就是"重复做一万遍加减乘除"。** 没有魔法。

## 2. 自由落体的两个式子

一个物体在空中往下掉，每一步做两件事：

```python
v = v + g * dt      # 新速度 = 旧速度 + 重力带来的变化
z = z + v * dt      # 新高度 = 旧高度 + 用【新速度】走的距离
```

其中 `g = -9.81`（重力加速度，负号表示向下）。

## 3. 顺序反了，答案就对不上

如果你写成：

```python
z = z + v * dt      # 先用【旧速度】更新位置
v = v + g * dt      # 再更新速度
```

结果会**系统性地偏高**，而且越跑越偏。

为什么？因为速度在这一步里是连续变化的，先用新速度更接近真实。这个做法有个名字叫**半隐式欧拉**（semi-implicit Euler）。

**MuJoCo 用的就是这个顺序。** 你把顺序写对，一千步之后能和 MuJoCo 的数字吻合到小数点后三位——这就是第 12 级的验收标准。

## 4. 亲手试一遍

```bash
conda activate eeg-arm
python
```

```python
>>> z, v, g, dt = 10.0, 0.0, -9.81, 0.001
>>> for _ in range(1000):
...     v = v + g * dt
...     z = z + v * dt
...
>>> print(z)
```

（`...` 是 Python 自动出现的。循环写完后**再敲一次回车**（敲个空行）才会退出循环。）

算出来的 z 大约在 **5.1** 附近。（自由落体 1 秒大约掉 4.9 米。）

再试试把两行顺序调过来，看看数字差多少。**这个差就是两种积分方法的区别。**

## 5. 这一课会用到的全部东西

| 写法 | 意思 |
|---|---|
| `for _ in range(n)` | 重复 n 次。（`_` 表示"这个计数变量我不用"，是习惯写法） |
| `v = v + g * dt` | 变量可以拿自己的旧值算新值；等号右边先算完，再赋值给左边 |
| `model.opt.timestep` | MuJoCo 的时间步长 |
| `mujoco.mj_step(model, data)` | **推进一步**（真正改 `data.qpos`，时间加 dt） |
| `mujoco.mj_forward(model, data)` | **只算一次**（不推进时间，`data.time` 不动） |

最后两个的区别以前提过，这一课是它真正见分晓的地方：**`mj_step` 是"时间往前走一格"，`mj_forward` 是"把当前状态算清楚"。**
