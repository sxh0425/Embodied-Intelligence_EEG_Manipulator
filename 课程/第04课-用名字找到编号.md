# 第 1 部分 · 这一课到底在干什么

**一句话：把"名字"翻译成"编号"。**

## 用图书馆打比方

你在图书馆想找《三体》：

1. 你脑子里记的是**书名**——`三体`
2. 但书架上摆的顺序，用的是**索书号**——`I247.5/1234`
3. 中间要靠**检索机**翻译一次

```
书名"三体"  ──检索机──>  索书号 I247.5/1234  ──>  找到书
```

MuJoCo 完全一样：

```
名字 "hand"  ──mj_name2id──>  编号 9  ──>  data.xpos[9]  =  夹爪在哪
```

**为什么要多这一道？**

因为电脑内部记东西用数字最快、最省地方。"hand" 这 4 个字母，电脑每次都要一个字母一个字母比对，几万次计算下来就慢了。所以模型一加载，MuJoCo 就把所有名字换成编号存起来。

**名字是给人看的，编号是给机器用的。** 你写代码时想要哪个东西，都得先做一次翻译。

# 第 2 部分 · 先搞清楚 model 和 data 的区别

这是最基础、也最容易搞混的一对。**搞清楚了后面全都顺。**

```python
model = mujoco.MjModel.from_xml_path("...scene.xml")   # 模型
data  = mujoco.MjData(model)                            # 数据
```

| | `model`（模型） | `data`（数据） |
|---|---|---|
| 中文 | 模型 | 数据 |
| 存什么 | 机械臂的**图纸** | 机械臂的**当前状态** |
| 会变吗 | **永远不变** | **每一步都在变** |
| 举例 | 有几节连杆、每节多长、关节装在哪、质量多少 | 每个关节现在转到几度、夹爪现在在哪 |
| 生活类比 | 游戏的角色设定表 | 这一局玩到现在的存档 |

**判断口诀：**

- 问"这台机械臂**有几节**" → 看 `model`
- 问"夹爪**现在**在哪" → 看 `data`

所以：`model.nbody` 是 body 的**总数**（永远 12 个），`data.xpos[9]` 是**当前**位置（会随机械臂动）。

### 一个坑

`data` 里的东西**不是自动更新的**。你改了关节角度，得喊一声"算一下"：

```python
mujoco.mj_forward(model, data)
```

不喊这一声，`data.xpos` 里全是 0。这是初学者最容易踩的坑。

# 第 3 部分 · body 是什么

**机械臂是一节一节拼起来的，每一节刚体就叫一个 body。**

这个模型里一共有 12 个 body（`model.nbody` = 12），真实的名单和它们的位置长这样：

```
编号   名字             世界坐标 [x, y, z]
 0     world            [0.0000  0.0000  0.0000]     <- 世界地基，不是机械臂
 1     link0            [0.0000  0.0000  0.0000]     <- 底座
 2     link1            [0.0000  0.0000  0.3330]
 3     link2            [0.0000  0.0000  0.3330]
 4     link3            [0.0000  0.0000  0.6490]
 5     link4            [0.0825  0.0000  0.6490]
 6     link5            [0.0000  0.0000  1.0330]
 7     link6            [0.0000  0.0000  1.0330]
 8     link7            [0.0880  0.0000  1.0330]
 9     hand             [0.0880  0.0000  0.9260]     <- 手（夹爪的底座）
10     left_finger      [0.0880  0.0000  0.8676]
11     right_finger     [0.0880  0.0000  0.8676]
```

（这是机械臂**初始姿势**下的值。你一改关节角度，第 2~11 行全会变。）

注意两点：

- **第 0 号是 `world`**，它代表整个场景的坐标原点，**不属于机械臂**。所以"机械臂有 11 节"而不是 12 节。
- **编号从 0 开始**，名字编号也是从 `link0` 开始。电脑里第一个永远是 0 号。

# 第 4 部分 · 这一课用到的全部 API

**只有三个，都在这里了。**

### 1. 名字 → 编号

```python
mujoco.mj_name2id(model, mujoco.mjtObj.mjOBJ_BODY, "hand")
```

| 位置 | 是什么 | 中文 |
|---|---|---|
| 第 1 个参数 `model` | 模型 | 在哪个模型里查 |
| 第 2 个参数 `mujoco.mjtObj.mjOBJ_BODY` | 查什么种类的对象 | 我要找的是 **body** |
| 第 3 个参数 `"hand"` | 名字 | 叫 "hand" 的那个 |
| **返回值** | 一个整数 | 它的编号，这里是 **9** |

读法：`mujoco` 里的 `mj_name2id`（MuJoCo **name to id**，名字转编号）。

`mjtObj.mjOBJ_BODY` 里的 `BODY` 可以换成别的：

| 换成 | 中文 |
|---|---|
| `mjOBJ_BODY` | 身体 / 连杆 |
| `mjOBJ_JOINT` | 关节 |
| `mjOBJ_GEOM` | 几何体（画出来能看见的那些形状） |
| `mjOBJ_SITE` | 标记点（模型里人为放的点） |

**查什么就写什么，写错了会返回 `-1`**（意思是"没找到"）。

### 2. 用编号取位置

```python
data.xpos[9]
```

读法：`data` 里的 `xpos`（**x** = 世界坐标系下的，**pos** = position 位置）。

返回一个**长度 3 的数组**：`[x, y, z]`，单位是**米**。

比如里面是 `[0.088, 0.0, 0.926]`，意思是：

- 往右 0.088 米
- 前后不动
- 高 0.926 米

（世界坐标系是右手系：**z 是竖直向上的**，x 和 y 是两个水平方向，三者互相垂直。z = 0 就是机械臂底座所在的地面高度。）

### 3. 编号 → 名字（反查）

```python
mujoco.mj_id2name(model, mujoco.mjtObj.mjOBJ_BODY, 9)
```

返回 `"hand"`。

注意别和 `mj_name2id` 记混——**两个名字里 `2` 的位置不一样**：

- `mj_name2id` = name **to** id = 名字 → 编号
- `mj_id2name` = id **to** name = 编号 → 名字

### 4. 总共几个

```python
model.nbody      # n = number, body = 身体  ->  12
```

# 第 7 部分 · 可能会遇到的情况

| 你看到的 | 意思是 | 怎么办 |
|---|---|---|
| `⬜ 还没写` | 没有 `return`（或者返回了 None） | 检查是不是忘了写 `return` |
| `❌` 后面跟着 `你的答案: None` | 同上 | 同上 |
| `❌` 你的答案是 `"hand"` | 你返回了**名字**，题目要的是**坐标** | 回去补上取位置的那一步 |
| `❌` 你的答案是 `[0. 0. 0.]` | `mj_forward` 没算过 | warmup 自己会算，检查你是不是把 `data.xpos` 写成了别的 |
| `NameError: name 'mujoco' is not defined` | 忘了 `import mujoco` | 但 warmup.py 顶部已经有了，一般不会 |
| `ModuleNotFoundError: No module named 'mujoco'` | 没激活环境 | 先 `conda activate eeg-arm` |
